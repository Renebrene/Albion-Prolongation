1. ОБЩАЯ ИНФОРМАЦИЯ
================================================================================

Название проекта: GeoPhoto
Тип: Progressive Web App (PWA)
Целевые платформы: Android (Chrome), iOS (Safari), Desktop (любой современный браузер)
Язык интерфейса: русский
Стек клиента: HTML5 + CSS3 + Vanilla JavaScript (без фреймворков)
Стек сервера: Node.js 18+ + Express.js + SQLite (better-sqlite3)
Админ-панель: чистый HTML + JavaScript

Назначение приложения:
- Съёмка фото через штатную камеру устройства (Android/iOS)
- Чтение GPS-координат из EXIF-данных фото
- Автоматическое определение адреса по базе известных локаций (радиус 10-100 м)
- Отправка фото на сервер с очередью и проверкой целостности
- Офлайн-работа с последующей синхронизацией
- Логирование действий с отправкой логов на сервер

5. КЛЮЧЕВЫЕ КОМПОНЕНТЫ КЛИЕНТА
================================================================================

PairingManager (pairing.js):
- pair(token, deviceName) — первичное сопряжение
- apiRequest(endpoint, options) — все запросы с X-Device-Token
- syncLocations() — POST /api/locations с массивом логов, обновление БД
- uploadPhoto(photo) — отправка фото с SHA-256 checksum
- checkStatus() — проверка валидности токена
- unpair() — отвязка устройства

PhotoCompressor (compression.js):
- 4 уровня: original (1.0), high (0.85/2048px), medium (0.70/1600px), low (0.50/1024px)
- compress(dataUrl, exifBinary) — сжатие через Canvas + вставка EXIF через piexif.insert()
- Настройка хранится в localStorage('compressionLevel')

Logger (logger.js):
- info(message, context), warn(...), error(...)
- Хранит до 500 записей, автоочистка старых
- Отправка на сервер при syncLocations()
- Очистка локального лога после успешной отправки

ExifReader (exif.js):
- readFromFile(file) → { gps: {lat, lon} | null, exifBinary: string | null }
- Конвертация DMS → десятичные градусы
- Возвращает бинарные EXIF для последующей вставки в сжатое фото

GeoPhotoDB (db.js):
- CRUD для photos, locations, logs
- findNearestLocation(lat, lon) — поиск по нарастающим радиусам: 10, 20, 30 ... 100 м
- Формула Haversine для расчёта расстояния

8. СЦЕНАРИИ ИСПОЛЬЗОВАНИЯ
================================================================================

СЪЁМКА И ОТПРАВКА ФОТО:
1. Пользователь нажимает на большую иконку камеры
2. Открывается системная камера Android/iOS
3. После съёмки:
   a) ExifReader читает GPS + бинарные EXIF
   b) PhotoCompressor сжимает фото с сохранением EXIF
   c) GeoPhotoDB ищет адрес по GPS (радиусы 10-100 м)
   d) Фото сохраняется в IndexedDB
   e) Автоматически выбирается в ленте
4. Пользователь нажимает кнопку отправки в шапке
5. Если адрес пуст — открывается экран редактирования
6. Иначе — отправка на сервер с checksum
7. Статус меняется на "sent"

СИНХРОНИЗАЦИЯ БАЗЫ:
- Автоматическая: раз в 24 часа (если включена)
- Ручная: кнопка в настройках
- При синхронизации:
  a) Собираются локальные логи
  b) POST /api/locations с массивом логов
  c) Сервер сохраняет логи, отдаёт новые локации
  d) Клиент обновляет IndexedDB
  e) Локальный лог очищается

ОТЗЫВ ТОКЕНА:
1. Админ нажимает "Отозвать" в админ-панели
2. Сервер ставит revoked=1 в БД
3. При следующем запросе клиента — 403 TOKEN_REVOKED
4. Клиент показывает уведомление, предлагает перейти в настройки
5. Пользователь может ввести новый токен

9. БЕЗОПАСНОСТЬ
================================================================================

Токены устройств:
- Генерация: crypto.randomBytes(32).toString('hex') = 64 hex chars
- Срок действия: настраивается (по умолчанию 365 дней)
- Хранение на клиенте: localStorage('deviceToken')
- Передача: заголовок X-Device-Token
- Проверка на сервере: существует + не отозван + не истёк
- last_seen обновляется при каждом запросе

Контрольные суммы:
- Клиент: SHA-256 от base64 изображения (Web Crypto API)
- Сервер: пересчитывает и сравнивает
- При несовпадении — 400 CHECKSUM_MISMATCH

Логи:
- Не содержат персональных данных
- Отправляются только при синхронизации
- Очищаются на клиенте после успешной отправки
- На сервере — автоочистка записей старше N дней

10. ОГРАНИЧЕНИЯ И ИЗВЕСТНЫЕ ПРОБЛЕМЫ
================================================================================

КЛИЕНТ:
- iOS Safari может удалять данные PWA при нехватке памяти
- Точность GPS: 5-20 м (ограничение браузеров)
- Размер кэша IndexedDB: ~50 МБ на iOS, ~10% диска на Android
- Background Sync работает только в Chrome
- Некоторые камеры/мессенджеры удаляют EXIF
- Сжатие фото: 1-3 секунды на среднем устройстве

СЕРВЕР:
- SQLite подходит для ~100 устройств, ~10000 фото
- Нет rate limiting (нужно добавить)
- Нет HTTPS (настраивается отдельно)
- Нет аутентификации админа кроме секретного ключа

- Отзыв: manage_tokens.py revoke "бригада1"; GeoPhoto перепроверяет токен

18.1. ЧТО ИЗМЕНИЛОСЬ

Запуск: при старте сервера (force), по кнопке «Синхронизировать» в PWA
(refresh=1), по кнопке в админке (force), раз в dbSyncMinutes минут.
1. GET /api/v1/integration/files — список файлов папки «база данных».
2. Выбор файла: locationsFile (с учётом суффиксов _1, _2) либо самый свежий
   xlsx/xls/ods по mtime.
3. Сравнение file_id + mtime + size с сохранённым состоянием; если не менялся —
   скачивание не выполняется.
4. Скачивание в server/cache/xlsx/ (хранится только последняя версия).
5. Парсинг, нормализация (имя, lat, lon), дедупликация.
6. DELETE + INSERT в таблицу locations (транзакция).
7. revision = sha256(отсортированные name|lat|lon)[:32].
8. settings: xlsx_file_id, xlsx_mtime, xlsx_size, xlsx_name, xlsx_cache_path,
   xlsx_last_check, xlsx_last_sync, locations_revision, xlsx_last_error.
При ошибке парсинга локации не заменяются, ошибка пишется в xlsx_last_error.
