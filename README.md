# Пролонгация (GeoPhoto)

PWA для съёмки фото, определения адреса по GPS из EXIF и отправки в файлохранилище
**albion-files** (`/home/alexice/projects/albion-files`).

База адресов хранится в файлохранилище в виде **XLSX**. Сервер GeoPhoto проверяет
свежесть файла, скачивает его в свой кэш, парсит парсером проекта **Локатор**,
переводит данные в SQL (SQLite) и отдаёт устройствам. Телефон хранит копию
в IndexedDB и работает без интернета.

## Архитектура

```
PWA (телефон)
   │  X-Device-Token: 8 кириллических букв (percent-encoding)
   ▼
GeoPhoto-сервер (Node.js + Express + SQLite)
   │  X-API-Key: тот же токен
   │  GET /api/v1/integration/files + download
   ▼
albion-files (файлохранилище)
   └── пролонгация/
       ├── база данных/
       │   └── locations.xlsx   ← источник адресов
       ├── бригада1/            ← фото + копия токена
       ├── бригада2/
       └── бригада3/
```

- Токен выдаётся в `albion-files` и привязан к папке бригады.
- GeoPhoto проверяет токен через `/api/v1/integration/verify`.
- Фото загружаются в папку, к которой привязан токен.
- XLSX скачивается в кэш `server/cache/xlsx/`, парсится и заменяет таблицу
  `locations` только если файл действительно изменился.

## Настройка

### 1. Папки и токены в albion-files

Создайте `пролонгация/база данных/бригада1..3`. UUID папки виден в `/f/<uuid>`.

```bash
cd /home/alexice/projects/albion-files

./venv/bin/python manage_tokens.py add-simple "бригада1" \
  --folder <uuid-бригады1> --token ТОКЕНБРА --scopes upload,delete,download
./venv/bin/python manage_tokens.py add-simple "бригада2" \
  --folder <uuid-бригады2> --token ТОКЕНБРБ --scopes upload,delete,download
./venv/bin/python manage_tokens.py add-simple "бригада3" \
  --folder <uuid-бригады3> --token ТОКЕНБРВ --scopes upload,delete,download

./venv/bin/python manage_tokens.py add-simple "база данных" \
  --folder <uuid-базы> --token ТОКЕНБАЗ --scopes upload,delete,download
```

Для папки «база данных» нужны права `download` (скачивание XLSX) и, при желании,
`delete` — не используются для выгрузки. Токен показывается один раз.

### 2. Конфигурация GeoPhoto

```bash
cd /home/alexice/projects/albion-prolong/server
cp integration.example.json integration.json
```

```json
{
    "storageBaseUrl": "http://127.0.0.1:5000",
    "dbFolderId": "<uuid папки «база данных»>",
    "dbToken": "токенбаз",
    "locationsFile": "locations.xlsx",
    "cacheDir": "cache",
    "xlsxCheckSeconds": 60,
    "dbSyncMinutes": 15,
    "verifyTtlSeconds": 60
}
```

- `locationsFile` — имя файла. Пустая строка: берётся самый свежий XLSX в папке.
  При совпадении имён Albion добавляет `_1`, `_2` — они тоже учитываются.
- `xlsxCheckSeconds` — как часто сервер проверяет метаданные файла при
  автоматической синхронизации (кнопка проверяет сразу).
- `dbSyncMinutes` — период фоновой проверки.

### 3. Запуск

```bash
cd /home/alexice/projects/albion-prolong/server
ADMIN_SECRET="длинный-секрет" npm start
```

- PWA: <http://localhost:3000/>
- Админ-панель: <http://localhost:3000/admin/>

Без `integration.json` сервер работает автономно: токены создаются в админ-панели

### 4. Телефон

В PWA: «Настройки» → адрес GeoPhoto-сервера → токен бригады (8 букв, регистр
не важен) → «Сохранить». Локации загрузятся сразу после сопряжения.

## Синхронизация XLSX

При старте, по кнопке «Синхронизировать» и раз в `dbSyncMinutes` минут:

1. Сервер получает список файлов папки «база данных».
2. Выбирает XLSX по имени/дате изменения.
3. Сравнивает `file_id`, `mtime` и размер с сохранённым состоянием. При фоновой
   проверке неизменённый файл не скачивается; кнопка/старт (`force`) перечитывают.
4. Иначе скачивает его в `server/cache/xlsx/` (хранится только последняя версия).
5. Запускает `xlsx_parse.py` → `vendor/xls_import.py` (парсер Локатора).
6. Берёт **«Наименование»**, **«Город»**, **«Адрес»**, **«Сторону»** и координаты.
   Если наименования нет, подпись собирается из города и адреса.
7. Заменяет таблицу `locations` (name, city, address, side, lat, lon) и
   вычисляет ревизию содержимого.
8. Устройства получают список только если ревизия изменилась.

Поддерживаются `.xlsx`, `.xlsm`, `.xls`, `.ods`; для `.xls` нужен `xlrd` или
LibreOffice, для `.xlsx` — только стандартная библиотека Python.

Форматы координат: `47.237201,39.816711`, `47,237201 39,816711`, отдельные
колонки «Широта»/«Долгота». Лишние строки и битые координаты пропускаются,
ошибки сохраняются в статусе.

При включённой XLSX-синхронизации ручное добавление/удаление локаций в
админ-панели отключено (`409 LOCATIONS_MANAGED_BY_XLSX`): источник — файл.

## API GeoPhoto

### Публичные

| Метод | Путь | Тело | Ответ |
|---|---|---|---|
| `POST` | `/api/pair` | `{ token, deviceName }` | `{ success, deviceName, expiresAt, brigade }` |
| `GET` | `/health` | — | `{ status, time }` |

### Защищённые (`X-Device-Token`)

| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/api/locations?since=&clientRevision=&refresh=` | логи + локации; `refresh=1` — сразу проверить XLSX |
| `POST` | `/api/upload` | фото с SHA-256 → папка бригады |
| `GET` | `/api/status` | устройство, бригада, ревизия локаций |

`POST /api/upload` принимает `{ id, name, city, address, gps, image, checksum }`.
`name` — «Наименование» из базы. Сервер присваивает имя `Наименование (N)`:
первое фото — `(1)`, второе — `(2)` и т. д. в пределах бригады; повторная
отправка того же `id` сохраняет имя и не создаёт копию в Albion. Имя с
итерацией используется и как `display_name`, и как имя файла в хранилище.

Если `clientRevision` совпадает с серверной, `locations` в ответе равно `null`
(данные не передаются), но логи принимаются.

Коды ошибок: `TOKEN_INVALID`, `TOKEN_REVOKED`, `TOKEN_EXPIRED`, `TOKEN_FORBIDDEN`,
`FOLDER_NOT_BOUND`, `CHECKSUM_MISMATCH`, `STORAGE_UNAVAILABLE`,
`STORAGE_UPLOAD_FAILED`, `XLSX_PARSE_FAILED`, `XLSX_NO_ROWS`,
`XLSX_PARSER_UNAVAILABLE`, `LOCATIONS_MANAGED_BY_XLSX`, `TOO_MANY_REQUESTS`.

### Админские (`X-Admin-Secret`)

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/admin/storage/status` | файл, ревизия, время проверки, кэш, ошибки |
| `POST` | `/admin/storage/sync` | принудительно проверить XLSX и обновить SQL |
| `GET` | `/admin/locations` | текущие локации из SQL |
| `GET` | `/admin/tokens` | сопряжённые устройства |
| `GET` | `/admin/logs`, `/admin/devices`, `/admin/stats` | диагностика |

## Токены

- 8 кириллических букв (`а–я`, `ё`), без цифр и пробелов; регистр не важен.
- В заголовке передаются в percent-encoding UTF-8; сервер принимает и raw UTF-8.
- В Albion хранится только SHA-256; отзыв — `manage_tokens.py revoke "бригада1"`.
- GeoPhoto перепроверяет токен каждые `verifyTtlSeconds`; при недоступности
  хранилища работает по кэшу до истечения срока.

## Окно фото

- **Город** — текстовое поле с подсказками из колонки `city` базы.
- **Адрес и сторона** — поле с подсказками вида `ул. Ленина, 1 (Б)`. При выбранном
  городе список фильтруется по нему.
- **Наименование** — показывается над полями и берётся из базы. При отправке
  сервер добавляет итерацию: `Наименование (1)`, `(2)`, … если фото несколько.
- Выбор города/адреса вручную сопоставляется с базой и подставляет
  «Наименование»; если совпадения нет, имя собирается из города и адреса.

## Клиент

- На главном экране — крупная кнопка **«Отправить»**. Кнопка синхронизации
  оставлена только в настройках («Синхронизировать базу»).
- Локации хранятся в IndexedDB (`locations`), фото и логи — там же.
- Синхронизация запускается при старте, при событии `online`, при возврате
  приложения на экран и по кнопке в настройках.
- Ревизия SQL хранится в `localStorage.locationsRevision`: если она не
  изменилась, список не перезаписывается.
- Service Worker кэширует статику (версия `geophoto-static-v6`).

## Обновление PWA

Версия приложения — `1.2.1` (видна в настройках, блок «О приложении»).

- При открытии приложение проверяет `sw.js` (`updateViaCache: none`). Новый
  Service Worker активируется, страница один раз перезагружается и получает
  новый код автоматически.
- Вручную: **Настройки → «Проверить обновление»**. Если обновление есть,
  приложение перезапустится.
- Если кнопка не помогла: полностью закройте PWA (свайп из списка приложений)
  и откройте снова. На Android можно открыть адрес в Chrome и обновить страницу.
- На iOS Safari: закройте PWA из переключателя приложений; если не обновилось —
  откройте адрес в Safari, обновите страницу и снова добавьте на экран «Домой».
- Не очищайте данные сайта/приложения без необходимости: в localStorage и
  IndexedDB лежат токен, настройки, очередь фото и локальная база локаций.

## Ограничения

- Для `.xls` нужен `xlrd` или LibreOffice; `.xlsx` читается без зависимостей.
- iOS Safari может очищать данные PWA при нехватке памяти.
- Background Sync есть только в Chrome; очередь отправляется при запуске и `online`.
- При нескольких XLSX в папке выбирается самый свежий (или совпадающий с
  `locationsFile`).
- После изменения `server.py` в albion-files требуется перезапуск сервиса.
